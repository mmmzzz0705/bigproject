## 故障：工作台 33 篇语料全部显示「已移出」（14:39 排查）

**现象**：`/api/corpus` 返回 total=33、total_chunks=42，32 篇 `in_index=false` + chunks=0。
文件在 `backend/data/corpus/` 里一个不少。

**结论：Milvus 集合元数据丢失，不是人为删除**（全程无 `DELETE /api/corpus` 调用）。
证据链：
1. PG `doc_meta` 表**只有 4 列**（doc_id/doc_name/source/upload_time），**没有 in_index/chunks 字段**
   → 这两个值是 `doc_stats()` 从 Milvus 实时统计的（`corpus.py:214` `in_index = chunks>0`）。
   所以「已移出」不是标记位，是 Milvus 里真的没向量。
2. 后端启动日志 `[init] Vector store = milvus (docs=0)` + `已有 0 个文本块，跳过导入`
   → 容器 14:37 启动时库就是空的。
3. `AUTO_INGEST_ON_STARTUP=false` → 空库**不会**自动重灌，于是空着。
4. MinIO `/minio_data/a-bucket/files/` 下**三个 collectionID** 的痕迹：
   - `469090338713070002`（09-15 02:32）
   - `469097101481960460`（09-15 09:38 建，insert_log 到 **09-17 11:42**、31 个 segment
     ≈ 33 篇；delta_log 到 09-17 11:45）← **853 条主库**
   - `469160056362369150`（09-18 06:38，今天新建的空集合）
5. Milvus 日志持续报 `collection not found[collection=469097101481960460]` /
   `not found database name` → querycoord 还看得到引用，rootcoord 元数据里没有它
   = **etcd 元数据与 MinIO 对象存储不一致**的典型表现。
6. 后端日志无 `[milvus] 维度不一致已重建`（milvus_store.py:88-101 的 drop 分支未触发），
   但旧日志已随容器重建丢失，无法 100% 排除该路径。
