## 工具经验：local office edit（editor_sdk）

- 走 `tencent-local-office-edit` skill，脚本在
  `.../workbuddy-builtin/skills/tencent-local-office-edit/edsdk.py`，
  用托管 python 跑：`python edsdk.py call <tool> file_id=... --json '{...}'`。
- 流程：`get_pool_status`(按 file_path 拿 file_id) → `schema <tool>` → `call` → `save_file`（不要 close_file）。
- 填模板占位符用 `doc_find_and_replace`（全文替换，自动处理索引偏移），
  比手算坐标 + `doc_replace_text` 稳。中文参数一律用 `--json` 传，别用 `k=v`（Git Bash 编码易炸）。
- 同样：`md_to_docx.py` 传**绝对路径**，相对中文路径在 Git Bash 下会 FileNotFoundError。
- **坑（必记）**：同名占位符（如 `[技术选择]` 出现 4 次）不能用 `doc_find_and_replace`，
  它全文替换；用 `doc_find` 取坐标 + `doc_replace_text` 逐个替换，且必须**从后往前**。
  更坑的是：位置降序 + 按原文顺序 zip 会导致**文本与位置整体反序**（方案A 拿到方案B 的内容）。
  正确写法 `zip(sorted(locs, key=begin, reverse=True), reversed(texts))`。
- 批量填充建议：写一次性 python 脚本，用 `subprocess` 调 `edsdk.py call`，
  参数用 `--json` + `json.dumps(ensure_ascii=False)`（不要用 `k=v`，中文会乱码）。
  改错后可用「临时标记法」纠正：先 A→@@T1@@、B→@@T2@@，再 @@T1@@→B、@@T2@@→A。
