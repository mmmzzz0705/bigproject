## 一键启动快捷方式（Docker 全栈）

新增根目录 `docker-up.bat` / `docker-down.bat` + 桌面快捷方式「启动政明白」「停止政明白」。

- **`docker-up.bat` 流程**：`docker info` 检引擎 → 优先 `docker-compose`（本机没有 compose v2
  插件）→ `up -d` → 轮询 `http://127.0.0.1:8080/api/health`（最多 180s）→ 打印 health 并开浏览器。
  `docker-down.bat` 只 `down`，命名卷保留。两者结尾 `pause`。
- **bat 写作要点**（都踩过）：
  - 全 ASCII —— `echo` 中文在 cmd 下会乱码；
  - 不用 `timeout` 做等待，改 `ping -n 3 127.0.0.1 >nul`：stdin 被重定向时 timeout 立刻返回，
    180s 的轮询会瞬间空转完；
  - `( )` 块内不嵌 powershell 命令（括号会破坏 cmd 解析），重定向照常、`|` 需 `^|`。
- **桌面快捷方式**由 `scripts/make_shortcuts.py` 生成：项目根用 `parents[1]` 推断（换机器重跑即可），
  桌面用 `SpecialFolders("Desktop")` 取（兼容 OneDrive 重定向），生成后回读 `TargetPath` 校验。
- **本机创建 .lnk 的通道限制（重要）**：PowerShell 工具里 `New-Object -ComObject WScript.Shell`
  被安全策略拦；`cscript` 跑 vbs 被拦（LOLBin）；从 bash 调 `cmd /c` 也被拦。
  **可用路径** = 隔离 venv `~/.workbuddy-ai/binaries/python/envs/default` 装 pywin32，
  写成 `.py` 文件再执行（`python -c` 内联仍可能被拦）。
- **实测**：`docker-up.bat` 退出码 0；`/api/health` →
  `doc_count=853 / vector_store=milvus / llm_provider=dashscope:deepseek-v4.1-flash`。
  `docker-down.bat` 未实测（避免打断正在运行的服务），结构与 up 一致。

## 追加：打开页面的快捷方式

- 新增 `open-page.bat`：`curl -s -f -m 5 .../api/health` 探测 → 在跑则 `start "" URL`，
  否则打印"服务未运行，先启动"并 `exit /b 1`。无 curl 的老系统跳过探测直接打开。
  意义：服务已在跑时不必再走一遍 `up`，服务没起时也不会落到"连接被拒绝"的死页。
- 桌面第三个快捷方式「打开政明白」；`scripts/make_shortcuts.py` 的 `SHORTCUTS` 现在是三项
  （启动 / 打开 / 停止），重跑脚本即可全量重建。
- **实测 .bat 的可靠通道（重要）**：PowerShell 工具执行 `.bat` **拿不到 stdout、
  返回码也不可信**（脚本明明 `exit /b 1`，工具却报 exit code 0）；
  `bash` 里 `cmd /c` 被拦。可靠做法 = Python
  `subprocess.run(["cmd","/c",bat], capture_output=True, text=True,
  stdin=subprocess.DEVNULL, timeout=...)`，**stdin 置空让末尾 `pause` 立即返回**，
  且必须同时打 `stderr` —— `docker compose` 的进度信息全在 stderr。
- 端到端实测（三态全覆盖）：
  - 服务停 → `open-page.bat` 返回 **1** + 提示文案 ✓
  - `docker-up.bat` → 重建网络 `group6_default` 与 6 容器 → health
    `doc_count=853`（卷保留，知识库完好）→ 返回 **0** ✓
  - 服务在跑 → `open-page.bat` 返回 **0** 并打开页面 ✓
- 期间观察到 gov-* 容器曾被 `compose down` 删除（非本次执行，疑似手动测「停止政明白」），
  之后已由 `docker-up.bat` 重新拉起，当前 6 容器正常、853 片段完好。
- 顺带确认：`docker-down.bat` 的 `down` 行为有效（容器确实被删干净，卷保留）。

## 新增功能：工作台（语料自助增删）— 2026-09-17 晚

- **需求**：网页多一栏「工作台」，可自行添加/删除语料。
- **实现**：
  - 后端 `app/services/corpus.py`（新建）：落盘→入库→元数据→删除清理的在线编排；
    `app/routers/corpus.py`（新建）：`GET /api/corpus`、`POST /api/corpus/upload`、
    `POST /api/corpus/text`、`DELETE /api/corpus/{doc_id}`、`POST /api/corpus/{doc_id}/reingest`。
  - 向量库新增能力：`BaseVectorStore.delete_by_doc_id()` / `doc_stats()`，
    Memory / Chroma / Milvus 三种实现都覆盖了（Milvus 用 `filter='doc_id == "..."'` + flush + BM25 失效）。
  - `ingest.ingest_file` 增加**幂等前置删除**（`_delete_existing`）：doc_id 由文件名哈希而来，
    重复导入同一篇会留重复片段、占满 Top-K，也会让删除只删掉一批。
  - 前端 `components/Workbench.vue` + `composables/useCorpus.js`，SideBar 顶部「智能问答 / 工作台」切换，
    App.vue 用 `view` 切换（`v-show` 保留对话状态）。
- **设计决策（不要改坏）**：
  - 上传语料落 `data/uploads`（可写），内置语料在 `data/corpus`（容器里 **:ro 挂载**）。
    分目录是为了让删除逻辑按"文件在哪"决定能不能删，不用猜。
  - origin 不入库（避免给 PG/SQLite 各写迁移），按文件所在目录实时判定：
    uploaded / builtin / missing。
  - **内置语料删除 = 只清向量，保留文件与 doc_meta 行**（`in_index=false`）。
    曾经把元数据行也删了 → reingest 找不到 source，永远恢复不回来（测试抓到的）。
  - 列表 `total_chunks` 用 `sum(doc_stats.values())`，**不能用 `store.count()`**：
    Milvus 是逻辑删除，row_count 仍算已删未 compaction 的行，界面会显示"删了但片段数没变"。
- **踩坑**：
  - `docker cp backend/app gov-backend:/app/app` 会**嵌套**成 `/app/app/app`（目标目录已存在时）。
    必须用 `docker cp backend/app/. gov-backend:/app/app/`。
  - 上传走 Nginx：`client_max_body_size` 默认 1MB，已在 nginx.conf 设 20m，否则大 PDF 直接 413 且到不了后端。
  - 构建镜像时清华源偶发 grpcio **哈希校验失败**、阿里云源在容器内 **DNS 解析失败**。
    已给 Dockerfile 加 `ARG PIP_INDEX_URL`（可 `--build-arg` 换源），重试通常能过。
  - 新增 `python-multipart` 依赖（`UploadFile` 必需，缺了上传接口直接 400）。
- **验证**：`tests/test_corpus.py` 17 passed（纯离线：memory 向量库 + 临时 SQLite）；
  全量 `pytest -q` 141 passed；容器内 E2E：上传 33→34 篇/853→856 片段、重复上传不翻倍、
  删除回落到 33/853、内置语料移出后 `chunks=0 & in_index=false` 且 reingest 恢复 12 片段、
  非法类型 .exe → 400。

### 第四轮：自审发现并修复两个缺陷

  内置语料源文件还在却永远无法 reingest。修复：落盘前 `_avoid_builtin_clash()` 改名

  新片段没进。修复：区分"更新"场景，失败时明确抛"旧片段已被移除，请重新上传"。
- **端到端问答验证（核心价值）**：上传带独特标记的语料 → 提问即命中（sources 第一条、
